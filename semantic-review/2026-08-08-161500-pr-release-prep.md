# v0.1 release prep: version reset, production hardening, QNN fix, font bump, Devin tests

Collapses the version history from 0.2.0/0.3.0 internal iteration down to a coherent 0.1.0 first public release. The change combines documentation consolidation, two targeted behavioral fixes (QNN false-positive, console.log removal), a systematic font size bump across 91 component files, production hardening (helmet, brotli, sourcemap strip, X-Robots-Tag), and 22 new Devin client unit tests.

Watch for: the font bump is mechanical and well-guarded by `truncate` preservation, but the graph canvas pass titles and sidebar tabs jumped from `text-xs`/`text-[11px]` to `text-sm` — wider text in fixed-width node boxes may clip differently on narrow viewports (possible). Tool count "27 vs 26" inconsistency in AGENTS.md (confirmed). Helmet's default headers (X-Content-Type-Options, X-Frame-Options) are fine for a local-first app but will block legitimate iframe embedding if someone embeds the UI in an Electron webview via a proxy (possible, low priority).

**Verdict**: APPROVED

---

## High-level view

The QNN fix is a two-line behavioral gate in `computeQnnCompatibleHardware` that returns `false` for `hostMode === "preparation"`, with a companion reclassification of QNN from `local` to `platformLocal` in `providerRuntimeKind.ts`. This means x64 Windows users no longer see QNN as a "local accelerator" but can still select it as a recipe target.

Production hardening is conservative. Helmet with CSP disabled adds only the non-intrusive defaults (X-Frame-Options SAMEORIGIN being the most impactful). Brotli is enabled both at build time (vite-plugin-compression) and serve time (express-static-gzip with `orderPreference: ["br", "gz"]`). The `filter` regex on the compression plugin ensures only compressible assets get doubled.

The font size bump applies a systematic +1 notch across 91 files. The diff shows `truncate` class counts are perfectly preserved (40 removed, 40 added), and existing `max-w-[...]` constraints were not reduced — layout overflow protections survived the bulk replacement. The highest-risk areas are graph canvas pass titles (now `text-sm` in fixed-width boxes) and sidebar tabs.

The Devin client tests cover the full lifecycle with proper fs/network mocking. They test meaningful edge cases (corrupt JSON, empty catalog, whitespace-only stream) but miss asserting that `logoutDevin()` clears cached tokens.

Documentation consolidation is internally consistent except for a "27 tools" vs "26 tools" discrepancy within AGENTS.md itself.

## QNN reclassification from `local` to `platformLocal`

The fix operates at two levels. `computeQnnCompatibleHardware` now returns `false` when `resolveQnnHostMode` returns `"preparation"` (Windows x64), preventing the false "QNN available locally" badge. `providerRuntimeKind.ts` moves QNN from the `local` case arm to `platformLocal`, adding it to `alwaysSelectableProviders()` so users can still pick it in the recipe builder regardless of hardware.

Edge case worth noting: Windows ARM64 with x64 emulation (Prism) would still report `process.arch === "arm64"`, so QNN correctly appears as a local accelerator on actual Snapdragon hardware. No regression path.

## Brotli pipeline: build-time generation and serve-time preference

Two `compression()` plugin instances in `vite.config.ts` produce both `.gz` and `.br` files. The `filter` regex (`/\.(js|css|html|svg|json)$/i`) limits compression to text-like assets — binary assets excluded. On the serve side, `express-static-gzip` with `orderPreference: ["br", "gz"]` gives brotli priority to clients that support it.

One potential issue: `vite-plugin-compression` 0.5.x has historically had quirks with `filter` as a RegExp (some versions documented string-only). If `.br` files aren't emitted during `pnpm build`, this is the first thing to check.

## Helmet X-Frame-Options and Tauri

Helmet's `X-Frame-Options: SAMEORIGIN` default will block loading the app inside a cross-origin iframe. For standalone localhost use this is irrelevant. For the Tauri desktop shell (which uses a local webview pointing at `localhost:3000`), the webview's origin matches — no conflict. But if someone proxies the app behind a different domain and iframes it, the header blocks it. Worth documenting but not blocking for v0.1.

## Font size bump: overflow risk assessment

The mapping applied:
- `text-[10px]` (254 removed) → `text-[11px]`
- `text-[11px]` (212 removed) → `text-xs` (12px)
- `text-xs` (325 removed) → `text-sm` (14px)
- `text-[9px]` badge labels (7 instances) preserved

Existing `max-w-[...]` constraints (`max-w-[140px]`, `max-w-[160px]`, `max-w-[170px]`, `max-w-[240px]`, `max-w-[280px]`) were not adjusted. With larger text in the same max-width boxes, content truncates slightly earlier (fewer visible characters), but the truncation itself is handled via ellipsis — no layout break.

Highest-risk spot: **GraphCanvas pass titles** bumped from `text-xs` to `text-sm` inside graph nodes with constrained visual width. Long pass names like "OnnxDynamicQuantization" (24 chars) or "IncDynamicQuantization" (22 chars) will show fewer characters before ellipsis. The `truncate` + `leading-snug` classes remain, so the failure mode is cosmetic (earlier truncation), not structural (overflow/reflow).

## Devin test gap: logout cache assertions

The tests mock `clearCachedCatalog` and `clearCachedUserJwt` but never verify these are called during `logoutDevin()`. Looking at the mock setup: both are imported from `./cloud-direct/catalog.ts` and `./cloud-direct/auth.ts` respectively. If the production `logoutDevin()` calls them (it should, to avoid stale tokens being used on next sign-in), this is an untested contract. Not a production bug — a test completeness gap.

## Documentation: tool count discrepancy

AGENTS.md introduces an internal inconsistency in this PR:
- Line in Architecture section: `"Python FastMCP stdio server (27 tools, 84 passes, 22 HW profiles)"` ✓
- Line in Kiro table: `"Workspace MCP server (Olive MCP — 26 tools for pass catalog, validation, troubleshooting)"` ✗
- Line in Kiro powers: `"documents all 26 MCP tools"` ✗

The `_TOOL_IMPORTS` dict in `mcp_server.py` has exactly 27 entries. The "26" references likely predate the addition of the most recent tool.
