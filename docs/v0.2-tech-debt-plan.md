> **Goal:** Eliminate structural debt that blocks the v0.3 agent evolution. After v0.2, the codebase is ready for a persistent stateful MCP agent, discriminated-union pass state, and component-level maintainability.
>

>

## Phase A: Critical Architecture (blocks v0.3 agent)

### Task 1: Persistent MCP connection (replace subprocess spawn)

**Objective:** Replace the per-call `python -c` subprocess spawn with a long-lived stdio MCP transport. This is the #1 prerequisite for the stateful agent.

**Current state:** `src/server/services/mcp/client.ts` spawns a fresh Python process per batch call (~500ms+ overhead). Circuit breaker mitigates repeated failures but doesn't fix latency.

**Steps:**
1. Use the `mcp` npm client library (or a lightweight JSON-RPC stdio transport) to maintain a persistent child process
2. On first tool call, spawn `python -m olive_mcp_server` with stdio transport
3. Keep the process alive between calls (reconnect on crash)
4. Remove the inline `python -c` script approach
5. Preserve the circuit breaker for process-crash scenarios (restart after cooldown)
6. Batch calls become sequential JSON-RPC messages on the same connection (~5ms per call vs ~500ms)
7. Update the breaker to track connection health, not per-call success/failure

**Verification:** `pnpm test:server` + integration tests pass. MCP tool calls return in <50ms (warm). Cold start still works (process spawned on demand).

**Risk:** The `mcp` npm package may not exist or may be server-only. If so, implement a raw JSON-RPC stdio client (spawn + readline + JSON parse). ~200 lines.

### Task 2: UIState.passes discriminated union

**Objective:** Replace the flat 30-field `passes` bag with a typed discriminated union per pass type. This is the #1 tech debt item (issue #11) and blocks programmatic pass manipulation by the agent.

**Current state:** `UIState.passes` is one object with all fields for all pass types. Every consumer must know which fields are relevant. The agent will need to construct/modify passes programmatically — a flat bag makes that error-prone.

**Steps:**
1. Define per-pass config types:
   ```typescript
   type QuantConfig = 
     | { method: 'awq'; groupSize: number; dampPercent: number; sym: boolean }
     | { method: 'gptq'; blockSize: number; groupSize: number; descAct: boolean }
     | { method: 'ptq'; precision: 'int4' | 'int8' | 'fp16' }
     // ...
   ```
2. Replace `passes: { ... }` with `passes: PassConfig[]` (ordered array, each with a discriminant)
3. Update `oliveRecipeBuilder.ts` to iterate the array (exhaustive switch)
4. Update `pipelineValidation.ts` CROSS_PASS_RULES to work with the new shape
5. Update `commitUiStateUpdate` coercion for the new structure
6. Update all 26+ feature panel components that read/write pass fields
7. Update all test fixtures

**Verification:** `pnpm test` + `pnpm validate:recipe` + `pnpm test:component` all pass. Recipe JSON output is identical for the same logical configuration.

**Risk:** Large surface area change. Consider a migration approach: keep the old `passes` shape as a compatibility layer with adapters, then migrate consumers incrementally.
